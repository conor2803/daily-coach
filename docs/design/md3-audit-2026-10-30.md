## Critical Issues

- **Navigation (0):** one 350-line scrolling `Column` holds everything: latest advice, permissions, places and settings (`MainActivity.kt:146-333`). No `Scaffold`, no `NavigationBar`, no destinations. The thing you open the app for (today's plan) shares a page with one-off setup.
- **Motion (0):** no animation anywhere. State changes (advice arriving, download progress, permission granted) snap into place.
- **Shape (2):** every container is a default `Card`; buttons and fields use defaults. `MaterialTheme.shapes` is never referenced, so nothing distinguishes a hero card from a settings row.
- **Layout (2):** one window size class, hard-coded `16.dp`/`14.dp`/`8.dp` spacing with no tokens (9 raw `dp` literals, 1 raw `sp`), no edge-to-edge (`enableEdgeToEdge` absent), content starts under a bare `statusBarsPadding`. Monospace preview text is `12.sp` outside the type scale.
- **Theming (3):** `MaterialTheme(colorScheme = if (dark) darkColorScheme() else lightColorScheme())` is the stock purple baseline — no brand seed, no `dynamicDarkColorScheme` on Android 12+, so the app ignores the user's wallpaper palette. `themes.xml` still parents `android:Theme.Material.Light.NoActionBar` (an MD2-era platform theme) and the launcher background is a hard-coded green that the in-app theme never uses.
- **Elevation (3):** six identical `Card`s with default tonal elevation; no hierarchy between `surface`, `surfaceContainer` and `surfaceContainerHigh`, so nothing reads as foreground.

## Warnings

- **Color tokens (6):** no hard-coded `Color(0x…)` (good), but only 4 `colorScheme` references; most text takes the default `onSurface` with no `onSurfaceVariant` for secondary text, and the error text uses `error` on `surface` rather than `errorContainer`/`onErrorContainer`.
- **Typography (5):** 12 `MaterialTheme.typography` uses with sensible roles (`headlineMedium`, `titleSmall`, `labelSmall`), but `bodySmall` doubles as both help text and status, the advice headline (`titleMedium`) is smaller than the app title, and `FontFamily.Monospace` is applied raw.
- **Components (4):** Material 3 composables throughout (`Card`, `Button`, `OutlinedButton`, `TextButton`, `OutlinedTextField`, `RadioButton`), but the permission list is hand-rolled `Row`s with "✓"/"•" text glyphs instead of `ListItem` + `Icon`, and places are a text list with `TextButton("Remove")` rather than list items with trailing icon buttons.
- **Accessibility (4):** touch targets are default (48dp) and the engine radio rows use `selectable(role = RadioButton)` (good), but there is no `contentDescription` anywhere, status is conveyed by glyph only, and the advice card has no semantics grouping.

## Passing

- No raw hex colours in Kotlin — every colour comes from the scheme.
- Material 3 library is the only UI library (no MD2 `android.widget` mixing).
- Light/dark both work via `isSystemInDarkTheme()`.

## Recommended Fixes (Priority Order)

1. **Give it a shape:** `Scaffold` + `NavigationBar` with three destinations — Today, Trends, Settings — so the daily plan stands alone.
2. **Theme properly:** `MaterialExpressiveTheme` with `dynamicDarkColorScheme`/`dynamicLightColorScheme` on Android 12+, a branded green seed scheme as the fallback, and a brand typeface (Manrope) for display/headline roles; `enableEdgeToEdge()`; drop the MD2 platform theme parent.
3. **Build hierarchy with surfaces and shape:** hero plan card on `primaryContainer`/`surfaceContainerHigh` with `shapes.extraLarge`; settings as `ListItem` groups on `surfaceContainerLow`; `outlineVariant` dividers.
4. **Add motion:** `MotionScheme.expressive()`, `AnimatedContent` for advice arriving, animated progress for the download, draw-in on charts.
5. **Replace hand-rolled rows** with `ListItem`, `Icon` and `IconButton`; add `contentDescription` and semantic grouping.
6. **Spacing tokens:** one `Spacing` object on the 8dp scale; no scattered literals.
